# 交互体验审查与改进

日期：2026-10-14。范围：网页管理后台（平台、用户、邀请、关怀）、网页学生端弹窗表单、微信小程序全部页面。

## 发现的问题

起因是管理页把新增、编辑表单直接铺在页面上，挤占核心列表。按同一思路逐页排查，归纳出六类问题：

| # | 问题 | 典型位置 | 对用户的影响 |
| --- | --- | --- | --- |
| 1 | 新增/编辑表单常驻页面顶部 | 平台管理（新增大区、新增学校、任命管理员三块表单）、用户管理、学校与邀请 | 进入页面先看到空表单，列表被推到首屏以下；改一行要滚动到页面另一处 |
| 2 | 编辑区、确认区出现在页面中部或底部，离触发按钮很远 | 平台“调整权限”滚回顶部表单；用户编辑/停用确认插在表单与列表之间；邀请“使用记录”追加到页面最底部 | 点了按钮看不到反应，容易以为没生效或重复点击 |
| 3 | 错误提示统一显示在页面顶部 | 平台、用户、邀请页；小程序树洞送温暖/举报、星图删除与生成图片 | 在页面下方操作时看不到错误 |
| 4 | 不可撤销或影响较大的操作缺少确认，或确认方式不一致 | “标记已跟进”一点即生效且不能撤回；树洞驳回/下架一点即生效；邀请停用为行内两连击；各页确认样式不同 | 误操作风险高，交互认知成本高 |
| 5 | 关闭表单静默丢弃已填写内容 | 网页打卡、日记、投稿、工具、服务表单弹窗按 Esc 或点遮罩；小程序树洞与星图弹层；切换工具或版本 | 写了很久的内容一下子没了，对学生尤其不友好 |
| 6 | 手机端信息层级不清 | 管理表格在 375px 宽度需要横向滚动，“操作”列在屏幕外；后台底部导航“学校与邀请”换行；小程序服务页长表单下方才是“我的申请” | 关键操作不可见；查进度要滑过整张表单 |

另有若干细节：状态以纯文字显示；用户搜索必须点“查询”按钮；分页不显示总页数；列表空状态没有下一步引导。

## 改进原则

1. **列表优先**：管理页首屏是列表本身。新增按钮放在列表标题右侧，与计数、筛选同一行。
2. **在原处完成**：新增、编辑、确认、详情一律用弹窗（网页）或底部弹层/系统确认框（小程序），就地出现、就地关闭，不打断页面位置。
3. **错误跟着表单走**：表单错误显示在弹窗内、提交按钮附近；行内操作的失败用轻提示（toast）。
4. **危险操作统一确认**：停用、撤销、重置密码、停用邀请、标记已跟进都用同一种确认弹窗，写清后果以及能否恢复；危险按钮用红色。
5. **不丢草稿**：有未保存输入时，关闭或切换前先确认；保存成功则直接关闭。
6. **手机端可操作**：表格在窄屏变为带字段名的卡片，操作按钮始终可见；导航文字不换行。

## 已实施的改进

### 网页管理后台

- **平台管理**：分为“大区 / 学校 / 管理员 / 操作记录”四个页签，页签上显示数量。每个页签只有一个列表，标题旁是主按钮（新增大区、新增学校、任命管理员）。
  - 新增、编辑、任命、调整权限、停用/启用、撤销都在弹窗中完成。
  - 学校列表可按大区筛选；学校的所属大区在编辑时显示为只读，并注明创建后不可迁移。
  - 当前登录账号标注“（我）”，不可操作的按钮置灰并给出原因。
- **用户管理**：工具栏包含即时搜索（输入后 0.3 秒自动查询）、类型筛选和“清除筛选”，“新增工作人员”放在列表标题旁。
  - 编辑资料与重置密码拆成两个弹窗；重置密码要求输入两次并校验一致。
  - 停用/启用、任命学校管理员、撤销管理员都经确认弹窗。
  - 分页显示“第 x / y 页”；空状态区分“无结果”和“还没有用户”。
- **学校与邀请**：学校汇总改为顶部紧凑条，邀请记录成为页面主体，可按状态筛选。
  - 生成邀请码在弹窗中完成，成功后在同一弹窗中醒目展示完整邀请码（仅此一次），需点“我已记录”才关闭。
  - 使用记录改为弹窗查看；停用邀请经确认，并说明不可恢复、已注册账号不受影响。
- **支持需求**：分为“待跟进 / 已跟进 / 全部”页签，默认显示待跟进；“标记已跟进”需确认，提示须在实际联系后再标记。
- **树洞审核**：纸条和回复的“驳回 / 下架”先弹出确认，引用待处理内容，并说明之后仍可在“已驳回”中重新通过；“审核通过”保持一键完成。
- **学生关怀**：筛选标签显示各状态人数；空状态区分“无匹配”和“还没有学生”。
- **通用**：新增 `FormDialog`、`ConfirmDialog`、`Tabs`、`ListHeader`、`ActiveBadge` 组件和 `useMutation`，各页面行为一致；启用/停用以彩色状态标签显示。

### 网页学生端

- 打卡、日记、投稿、服务申请、结构化表单、成长工具和关怀跟进弹窗：有未保存输入时，按 Esc、点关闭或点遮罩会先弹出“放弃未保存的内容？”。选“取消”保留内容；保存成功后直接关闭，不会多问。

### 手机网页

- 管理表格在 760px 以下变为卡片：首行为名称，其余字段带标签，操作按钮在卡片底部，始终可见。
- 后台底部导航中的“学校与邀请”缩写为“邀请”，当前页标记 `aria-current`。

### 微信小程序

- **星图**：写日记从页面内展开的长表单改为底部弹层，提交按钮固定在弹层底部，页签与列表保持原位；错误显示在弹层内；有内容时关闭会先确认放弃。
- **树洞**：投稿或回应弹层有内容时，关闭前先确认；送温暖和举报失败改用轻提示，不再显示在页面顶部。
- **服务需求**：分为“提交申请 / 我的申请”两个页签。提交后自动切到“我的申请”并提示成功；从“我的 → 服务需求与处理状态”进入时直接显示申请列表；支持下拉刷新。
- **成长工具**：保存时的校验错误显示在保存按钮上方，并同时轻提示；已填写时切换工具或版本会先确认，避免清空答案。
- **星图删除、生成图片、保存相册**：结果和失败都就地提示；无相册权限时用对话框说明处理方法。

## 未纳入本轮

- 小程序各页的页签样式本轮新增了全局 `.seg-tabs`，但只用在服务页；星图、树洞、工具页仍各用自己的样式（外观一致，代码尚未合并）。
- 本轮在 Node 中验证了小程序的页面事件与逻辑，没有在微信开发者工具或真机上走查新弹层的视觉效果和手势。

## 第二轮：按角色降低上手难度（2026-10-14）

权限分级后，四种身份看到的页面和能做的事各不相同，新用户容易困惑“我是谁、能做什么、下一步做什么”。从五个角度改进：

| 角度 | 问题 | 改进 |
| --- | --- | --- |
| 我是谁 | 管理员顶部只显示大区选择器，看不出自己的身份和范围 | 后台右上角显示“学校管理员 · 第一学校”等身份范围标签；点击打开账号菜单，列出“我能做什么”和不能做的事，并链接到指南对应章节 |
| 怎么做 | 说明分散在开发文档里，面向使用者的说明缺失 | 新增按角色编写的 [使用指南](guide/index.html)（应用内 `/guide/` 可直接打开）：角色权限表、每个角色的首次使用与日常任务步骤、关怀提示规则、常见问题；每个后台页面标题旁的“使用帮助”直达对应章节 |
| 下一步做什么 | 管理员登录后要自己判断先处理什么 | 关怀概览顶部“今天先做这几件事”按优先级列出待处理事项（优先关怀学生、待审树洞、待跟进需求、尚无学生时生成邀请码），一键进入；侧栏和手机底部导航显示待处理数量 |
| 第一次来 | 学生注册后面对一整页功能 | 网页和小程序首页显示“从这里开始”三步（记录心情、写星图、看树洞），可永久关闭；小程序“我的 → 使用帮助”随时查看学生指南 |
| 登录卡住 | 管理员不清楚该选哪个登录方式；学生不知道邀请码从哪来 | 后台登录说明两种登录方式各适用于谁；学生登录处提示邀请码向本校老师索取；登录框底部链接到常见问题 |

指南中提到的每个按钮名称都已与界面文字逐一核对。
