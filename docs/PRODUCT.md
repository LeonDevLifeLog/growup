# 成长健研社：功能与实现基线

日期：2026-10-14。交付：微信原生小程序、浏览器学生端预览、网页管理后台、本地 API 与 SQLite。本系统与成长健研社官网由同一团队自主开发，署名统一为“成长健研社”，品牌定位统一为“青少年身心健康成长服务品牌”。网页端、小程序与管理后台均使用自身产品口吻介绍功能；界面不出现“原站”“参考站”“借鉴”“独立复现”等第三方归属表述。

## 1. 需求与官网功能基线

| 诉求 | 官网已有内容 | 本项目设计 |
| --- | --- | --- |
| 区域入口与账号隔离 | 两个公开页面未观察到区域账号功能 | 平台维护动态大区；学校邀请码绑定区域与学校；服务端校验区域，账号不能切区登录 |
| 连续情绪低迷预警 | 成长站有描述性观测理念，无已验证的后台预警 | 上海时区自然日；1–2 分为低落；连续 3–4 天黄色、≥5 天红色；最近连续 7 天≥3 分绿色；不足样本为观察中 |
| 成长内容模块 | Star-Track、STARMAP、校园/家庭服务、技能输出、理念、共研室 | 提供18个观察工具、抗碎片化研究、星图关系及4份需求反馈表；提供心情打卡、内容阅读与区域服务跟进 |
| 匿名树洞 | 化名留言、回复、元气糖、随机浏览、我是谁/对谁说 | 同区域匿名树洞；主题筛选、留言、回复、送温暖、举报；先审后发；后台审核 |

官网：https://sdsqsnwh.cn/cz/ ，匿名表达页面：https://sdsqsnwh.cn/bk/es 。网页与小程序共享成长工具、表单、记录和报告能力，使用账号管理与区域权限。

Star-Track 包含中长期9个工具（4CR青少年/家庭、睡眠、青春期青少年/家庭、数字产品、亲子青少年/家庭、饮食体重）与现状分析9个工具（压力韧性、睡眠、数字产品、亲子、饮食体重、人际、口腔视力、青春期、反省规划）；另有抗碎片化成长问答。保留题目、年龄/场景版本、输入和报告规则，在网页弹层与小程序内部填写、保存和回顾。报告用于描述性观察，不作医学诊断；课程、活动和专业支持由工作人员沟通安排。

## 2. 用户流程与边界

学生：选择区域 → 输入账号/密码或用学校邀请码注册 → 成长首页 → 心情打卡/星图日记/成长探索/匿名树洞 → 我的记录。

平台管理员：独立平台入口登录 → 维护大区与学校 → 创建、停用管理员账号或重置密码 → 查看管理操作记录。

大区/学校管理员：选择所属大区登录 → 本区/本校仪表盘 → 学生关怀、树洞审核、服务跟进。学校管理员另可生成和停用本校邀请码；大区管理员查看本区邀请和使用记录。

账号注册使用学校邀请码，邀请码决定区域和学校，不能由客户端任意声明学校归属。系统不开放自助管理员注册。平台管理员负责组织与管理员账号，不进入学生关怀接口；大区管理员仅能操作本区数据，学校管理员仅能操作本校数据。客户端传递的区域、学校、角色和用户 ID 不作为授权依据。

首版允许账号密码登录，微信小程序使用同一 API。真实微信身份、监护人授权流程、正式学校账号导入和消息订阅属于上线接入工作，不声称已完成。

## 3. 预警规则与状态

心情：1 很低落、2 有点低落、3 还不错、4 很开心、5 超开心。每天可提交/更新一条，日期由服务器按 Asia/Shanghai 生成，客户端不能补写历史时间。重复提交是当日更新，不增加连续天数。

连续低落以最新一次打卡为锚，允许最新记录为今天或昨天；超过一个自然日未打卡则标为“待补充”，不默认为健康。断签中断连续；非低落打卡中断低落序列。3–4 天黄色“需要关注”，≥5 天红色“优先关怀”；最近连续 7 天均≥3 分为绿色“状态平稳”，其他为灰色“观察中”。红黄提示只在管理端出现，学生端用支持性反馈，不给孩子贴风险标签。

当前状态由打卡记录即时计算，后台跟进记录单独保存，不用“已跟进”覆盖仍存在的低落状态。首版“报警”是后台可见待关注列表和计数，不代表短信/微信告警已送达。阈值是用户需求的产品规则，不构成临床诊断。

## 4. 树洞与数据最小化

树洞在本区域内展示化名、主题、正文、发布时间、温暖数及已审核回复，不返回作者账号、真实身份、学校、用户 ID。匿名是对其他学生匿名；服务端为审核和举报追溯保存作者关联，后台普通审核列表也不展示学生身份。不得宣称绝对匿名。

发帖与回复先审后发；发帖人可在“我的纸条”查看待审核状态。大区管理员不能审核别区内容，学校管理员不能审核外校内容；跨校回复交由大区管理员审核；学生看不到待审/驳回内容。送温暖每人每帖每天一次、不可撤销；服务器唯一约束防重复。举报立即从公共列表隐藏并进入人工审核。禁止私信、陌生人联系和公开排名。紧急求助入口引导联系信任的成人/当地紧急服务，首版不假装提供即时在线咨询。

情绪备注、日记仅本人可见，管理端仅展示心情分数与日期用于关怀；后台跟进说明不在学生端公开。服务申请由本区大区管理员及本校学校管理员查看；大区管理员本人提交的教师需求仅在大区范围处理。输入长度受限，服务器验证，输出按文本呈现。

## 5. 实现结构

- `server/`：Node.js 内置 HTTP + SQLite，密码 scrypt、随机会话令牌、角色/区域授权、接口校验、审核及测试。
- `web/`：React + Vite + CSS；桌面自适应学生端，手机底部导航；独立管理员入口。
- `miniprogram/`：原生 WXML/WXSS/JS，直接导入微信开发者工具；不以 H5 套壳替代原生小程序。
- `docs/`：分析、API 契约、运行方式与验证结果。

学生端视觉：温暖的米白底、深森林绿、黄绿点缀；清晰标题、轻量线条、局部植物插画。后台保持同一色系，列表以颜色+文字表达关注级别。支持窄屏、键盘焦点、表单错误和加载状态。

## 6. 成长工具与服务

工具定义及评分仅由服务端统一维护，两端从 `/tools` 获取同一字段契约；不能在客户端传入报告得分。9个持续记录工具保留各自每日/周反思/活动/压力等子页签，同一工具、子页签、日期更新为一条；10个问答工具（含抗碎片化研究）保留多次完成记录。记录、答案、报告均仅本人可读写，不能通过区域管理员身份访问他人的工具数据。问答月报呈现当月最近一次结果，不把不同年龄版本混合平均。

STARMAP 提供完整文字、简短文字或仅心情记录、三级感受强度、最多6个标签和小目标。标签频次组成节点，同篇记录中的标签共现组成连线；支持搜索、删除、JSON备份/合并与选择片段导出；网页保存SVG，小程序提供canvas图片生成与保存相册控件（平台交互待真机验证）。网页版与小程序通过同一账号访问记录。星图统计不参与学校打卡预警。

青少年成长需求、教师需求与身心状态、活动服务反馈、使用体验反馈在两端内部填写，通过区域后台跟进。反馈关联当前账号，按本人、本区大区管理员及本校学校管理员的权限可见。现有管理员可提交教师需求，不因表单中自述职务获得任何新角色。

月拾WE、家庭/校园/技能服务提供产品介绍与需求提交，具体活动、课程及合作安排由所在区域工作人员确认。技术来源与版本证据保留在内部文档，不进入产品介绍。

详细字段、评分规则、差异及证据见 `MIGRATION_QUESTIONNAIRES.md`、`MIGRATION_TRACKERS.md` 和 `API.md`。

## 7. 验收

1. 海南账号尝试山东登录被服务器拒绝；伪造区域参数不能跨区取数。
2. 自助注册不能获取管理员权限；邀请码与区域不一致被拒绝。
3. 连续 2/3/4/5/6 天、断签、当天更新、时区换日与长期未打卡有自动化测试。
4. 学生不能调用管理接口，管理员无法读取别区学生或审核别区内容。
5. 树洞公共返回值不含身份字段；待审不可见；举报隐藏；每日温暖防重。
6. 日记与备注不泄露；刷新与服务重启后 SQLite 数据存在。
7. 浏览器完成登录、打卡、日记、树洞投稿、后台审核与跟进，并验证 375px 与桌面布局。
8. 19个工具可在两端内部填写、保存、查看报告、历史与月报，原有18工具分类完整，无复制链接/外站跳转。
9. 问答所有年龄/场景版本与公开评分函数完成对照；非法答案、缺答及伪造分数被服务器拒绝。
10. 工具与星图导入预校验、事务合并、不信任导入身份及得分，导出只含本人记录，跨账号和跨区域均不能读取。
11. 星图真实标签共现、搜索、删除、心情与小目标、4份结构化表单以及后台可见范围有接口与界面证据。
12. 小程序完成静态与真实WXML编译；只有完整开发者工具与真机验证后才能宣称微信运行通过。

## 8. 上线前待接入

真实微信 AppID 与 HTTPS 域名白名单、学校/区域正式名单及邀请码、监护人授权与隐私告知、人工审核与关怀人员及响应流程、通知通道、服务器部署与备份。首版种子数据全部为虚构演示数据；演示账号仅在显式 `DEMO_MODE=1` 时生成。

## 9. 正式组织、邀请注册与容器部署

目标：平台管理员维护大区、学校与管理员账号；学校管理员生成本校邀请码；学生在小程序或网页核对区域和学校后，自行设置账号密码完成注册。默认运行不生成大区、学校、演示账号或邀请码。

| 角色 | 管理范围 | 可执行操作 |
| --- | --- | --- |
| 平台管理员 | 平台组织及管理员账号 | 新增/更名/停用大区、学校；创建三类管理员；更名/停用账号、重置密码；查看管理审计 |
| 大区管理员 | 仅本区 | 学生关怀、跟进、树洞审核、服务处理；查看本区学校与邀请使用记录 |
| 学校管理员 | 仅本校 | 学生关怀、跟进、树洞审核、服务处理；生成/停用本校邀请码、查看使用记录 |
| 学生 | 本人记录和同区匿名社区 | 凭本校邀请码自助注册、记录与探索；无后台权限 |

- 大区、学校和管理员账号由平台配置，不写死区域。首位平台管理员通过本机或容器受控初始化命令创建，只接受标准输入凭据，不设默认密码，不开放管理员自助注册。后续管理员由平台界面创建。
- 学校归属、管理员角色与归属创建后固定；需要调整时停用旧账号并新建，保留历史关联。停用区域、学校、账号或重置密码会撤销相应会话；停用期间拒绝登录、取数及注册。管理员可以修改本人密码。
- 邀请码由学校管理员发起，服务器生成96位随机值，仅创建时展示完整值，数据库保存SHA256摘要及尾号；绑定学校，有效期1–365天、名额1–10000人。后台展示备注、状态、到期时间、已用/总名额及学生注册记录；停用邀请不影响已注册账号。
- 注册前可核对学校；最终提交仍由服务器重验邀请码。账号创建、名额消费、邀请使用记录和会话在同一事务内完成。重复账号、过期、停用、用尽、跨区和并发争用不得超发名额或产生错误归属。
- 两端注册有确认密码、账号格式与学校核对；无邀请码向学校申请。正式模式不显示演示入口。区域由API下发，网页下拉框与小程序原生选择器收起展示；两端登录页均不展示演示账号或自动填充入口，演示使用方法保留在README。
- 旧库保留账号、记录与组织，旧admin迁为大区管理员；旧邀请码转换为摘要，升级后30天到期、10000个后续注册名额，历史注册不追溯补计。升级前备份，升级后由平台为各校补建学校管理员。
- Docker多阶段构建API与网页，以非root用户在正式模式运行；SQLite使用持久化命名卷，配置健康检查和重启策略。

验收：空正式库初始化平台管理员 → 平台新增大区/学校/管理员 → 学校登录发邀请 → 学生两端核对学校并自行注册 → 退出重登 → 后台查看使用记录 → 停用邀请阻止新注册。跨区、跨校、越权、过期、停用、限额、重复账号、并发和旧库升级有自动化验证；实际容器验证健康、完整注册和重建后的数据保留。公网HTTPS与微信真机发布需另行完成。
