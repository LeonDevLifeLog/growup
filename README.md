# 成长健研社

青少年身心健康成长服务品牌。

面向校园的青少年成长陪伴应用。包含原生微信小程序、可在浏览器体验的学生端、独立网页管理后台，以及真实 SQLite API。区域账号隔离、每日心情记录、红黄绿关怀提示、私人日记、匿名树洞审核与服务跟进均在本地服务运行。

## 一键体验

```sh
./start.sh            # 演示模式：虚构大区、学校和账号，打开即可登录体验
./start.sh --prod     # 正式模式：空数据库，首次打开进入初始化向导
```

已安装 Node.js 22.13+ 时直接本机运行（自动安装依赖并构建）；否则自动改用 Docker。启动后打开 <http://127.0.0.1:8787/>，终端会显示演示账号（如 `hainan.student` / `hainan.admin`，密码 `Growup123!`，登录时选择“海南”）。常用参数：`--docker` 强制使用 Docker、`--port 9000` 换端口、`--stop` 停止 Docker 方式启动的服务、`--reset` 清空演示数据。设置 `GROWUP_IMAGE=ghcr.io/<owner>/<repo>:latest` 可直接使用 CI 发布的镜像而不在本地构建。

Windows 或不使用 bash 时，安装依赖后运行 `npm run demo`（正式模式加 `-- --prod`），效果相同。

## 持续集成与镜像发布

`.github/workflows/ci.yml` 在 GitHub 上对每次推送和合并请求执行：格式检查、网页构建、服务端测试、小程序检查、浏览器测试（截图作为构建产物保存14天），然后构建镜像并运行容器冒烟测试与全新安装全流程测试。推送到 `main` 或 `v*` 标签时，将 `linux/amd64`、`linux/arm64` 镜像发布到 `ghcr.io/<owner>/<repo>`：`main` 对应 `latest`，`v1.2.3` 标签对应 `1.2.3` 与 `1.2`，另有 `sha-<提交>` 标签。合并请求只构建和测试，不发布。发布使用仓库自带的 `GITHUB_TOKEN`，无需额外密钥；首次发布后包默认私有，如需匿名拉取，请在 GitHub 包设置中改为公开。

## 本地运行

需要 Node.js 22.13+（建议 24+；本次验证 26.8.1）、npm。浏览器测试还需本机 Google Chrome。

```sh
npm ci --registry=https://registry.npmmirror.com
npm run dev
```

- 学生端：<http://127.0.0.1:5173/>
- 关怀后台：<http://127.0.0.1:5173/#admin>
- API：<http://127.0.0.1:8787/api/health>

`npm run dev` 与 `npm start` 默认均为正式模式，使用 `data/growup.sqlite`，新库不预置组织、账号或邀请码。首次打开网页会进入初始化向导，创建平台管理员（可顺手开通第一个大区和学校），之后在网页后台开通其余组织和管理员。大区从API动态加载。

如需独立虚构数据体验，显式运行 `DEMO_MODE=1 npm run dev`，使用 `data/demo.sqlite`；两类数据库拒绝混用。登录页不展示演示账号、密码或一键填充入口；需要体验时按下表手动输入。

## 微信小程序

在微信开发者工具中导入 `miniprogram/`。原生 WXML/WXSS/JS，10 个页面、5 个 Tab。API 配置见 `miniprogram/config.js`；AppID由微信项目配置管理。详细导入和真机网络说明见 [小程序说明](miniprogram/README.md)。

当前已完成源码和静态结构检查，全部 10 个页面通过开发者工具内置 `wcc` 的独立 WXML 编译；CLI 被“服务端口已关闭”阻止，尚未取得 IDE 完整项目编译或真机结果。实际发布需要微信 AppID、HTTPS API 与合法域名配置。成长工具通过原生页面填写与生成结果，不依赖外站业务域名、复制链接或外站跳转。

## 本地功能

- 使用者说明见按角色编写的 [使用指南](docs/guide/index.html)（运行后访问 `/guide/`），后台各页“使用帮助”直达对应章节。
- 管理页以列表为主：新增、编辑和确认在弹窗中完成，手机上表格变为卡片；有未保存输入的弹窗关闭前会先确认。交互审查见 [docs/UX_REVIEW.md](docs/UX_REVIEW.md)。
- 用户管理支持账号检索、分页、人员建档、资料编辑、停用和密码重置，按权限分级：平台管理全部用户并任命三类管理员；大区管理员管理本区下级用户并任命本区学校管理员；学校管理员管理本校学生与待授权人员，不能任命。未登录不展示管理菜单。平台维护动态大区、学校与三类管理员；大区管理员仅本区，学校管理员仅本校。学校生成限时限额邀请码，学生核对学校并自设账号密码注册；后台可查使用记录并停用邀请。
- 1–5 级心情，每个上海自然日一条，可更新；连续低落 3–4 天黄色、≥5 天红色、最近连续 7 天均≥3 分绿色；断签及样本不足独立说明。
- 学生端不展示风险标签。管理端提供当前提示、分数日期和人工跟进记录；不读取私人日记、心情备注和标签。
- 区域内化名树洞，先审后发、回复审核、每日一次温暖、举报立即隐藏、本人查看审核状态。
- 18 个 Star-Track 工具原生化：9个持续记录工具与9个现状问答工具；另有抗碎片化研究问答，共19个工具。保留年龄、场景和记录子页签，提供本人报告、月度回顾与系统内历史记录。
- STARMAP 私人日记支持心情/感受强度/标签/小目标、共现关系星图、搜索删除；网页保存SVG、小程序提供生成图片及保存相册控件。
- 青少年成长需求、教师需求、活动服务反馈、使用体验反馈4份结构化表单，在应用内填写并由本区域后台跟进。
- 本地预警是管理后台提醒，尚未接入微信订阅、短信或外部报警推送。

成长健研社官网、网页学生端、微信小程序与关怀管理后台属于同一产品体系，使用统一品牌。官网入口：[成长健研社](https://sdsqsnwh.cn/cz/)。功能范围和验收规则见 [PRODUCT](docs/PRODUCT.md)。

Star-Track、STARMAP、抗碎片化成长观察及需求反馈均可在应用内完成。个人记录和报告按账号持久保存在系统中，可跨网页和小程序回顾，无需手工导入导出JSON。工具规则见[问答工具说明](docs/MIGRATION_QUESTIONNAIRES.md)及[长期观察说明](docs/MIGRATION_TRACKERS.md)。

成长报告用于自我了解与交流，不构成医学诊断。课程、活动与支持需求由所属区域工作人员跟进，具体安排在沟通后确认。

## 构建与运行

正式容器部署使用 `docker compose up -d --build`，默认端口 `127.0.0.1:8080`，演示模式关闭，SQLite 保存在持久化命名卷。管理员初始化、域名接入与运维步骤见 [Docker 部署](docs/DEPLOYMENT.md)。镜像构建后可用 `npm run test:docker` 验证正式空库、初始化、非 root 运行和重建后的数据保留，用 `npm run test:docker:fresh` 在全新容器中只通过浏览器走完“初始化 → 开通 → 注册 → 求助 → 回复”全链路；两项测试只使用并清理独立临时卷。

```sh
npm run build
DEMO_MODE=1 npm start     # 本地构建产物＋独立演示库，8787端口
```

正式首次启动后，浏览器打开站点即进入“首次安装初始化”向导，依次创建平台管理员、可选开通第一个大区与学校；完成后向导永久关闭。公网部署可设置 `SETUP_TOKEN` 环境变量，向导会要求输入该口令。命令行 `node server/bootstrap.mjs < operator.json` 仅作为应急方式保留。

初始化只能创建首位平台管理员，已有平台管理员时拒绝，不覆盖账号。之后访问后台选择“平台管理员登录”，在“平台管理”的“大区”“学校”页签点击新增；在“用户管理”点击“新增工作人员”建档，再到“平台管理 → 管理员”点击“任命管理员”，从已有用户任命大区/学校管理员。任命沿用账号和密码，调整或撤销权限使旧会话失效。学校管理员登录后在“学校与邀请”生成本校邀请码；学生在网页或小程序核对学校、自设账号密码完成注册。完整邀请码只在生成时显示，后台保留尾号、状态、名额和使用记录。区域与学校数量由平台配置。初始化口令、应急命令及升级说明见 [Docker 部署](docs/DEPLOYMENT.md)。

环境变量：`PORT`（8787）、`HOST`（127.0.0.1）、`DATA_PATH`（数据库路径）、`DEMO_MODE`（仅 `1` 开启）。真机局域网联调可显式 `HOST=0.0.0.0 DEMO_MODE=1 npm start`，小程序 API 使用电脑局域网地址；不要把手机 `127.0.0.1` 当作电脑地址。

正式提供服务还需实际学校与区域信息、学校/监护人授权和隐私流程、内容使用许可、关怀和审核值班安排、HTTPS/备份与数据删除流程、通知通道。当前代码没有部署到公网，也未发布到微信。
